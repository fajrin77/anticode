# Perbaikan dan verifikasi anticode — 10 September 2026

Perbaikan mencakup delapan temuan audit serta masalah tambahan pada alur desktop dan remote HP. Desain utama dipertahankan. Pengujian memakai profil Electron dan workspace sementara, serta server OpenAI-compatible lokal; tidak menggunakan kuota provider sungguhan.

## Perubahan

- Satu registry run untuk desktop dan HP: mencegah run bersamaan dalam sesi yang sama, menjaga lock selama pembatalan, mendukung pembatalan lintas perangkat.
- Desktop menyimpan run per sesi; membuka tab lain tidak menimpa status pekerjaan sebelumnya. Run aktif dipulihkan saat renderer dimuat ulang.
- Pembatalan diperiksa sebelum preview, approval, dan eksekusi tool. Menunggu stream provider dapat dibatalkan walaupun iterator SDK lambat berhenti. Event Pause tetap membersihkan status run.
- Browser context, halaman, dan catatan network dipisahkan per sesi; initialization bersama tidak membuat browser ganda.
- Output terminal dibatasi selama penerimaan. Exit code bukan nol dilaporkan sebagai kegagalan tool. Fetch memiliki timeout dan batas teks.
- Pemangkasan konteks menyimpan sebanyak mungkin giliran yang muat, tanpa memutus pasangan tool. Transcript lengkap terpisah dari konteks yang diringkas.
- Run dibatasi 100 giliran model atau 2 juta token kumulatif; kelanjutan dilakukan melalui prompt baru. Prompt yang melampaui kapasitas konteks menghasilkan pesan yang jelas.
- Sesi disimpan secara atomik di `sessions.json` dalam direktori data aplikasi. Restart dan pergantian model mempertahankan percakapan. Metadata tab, penggunaan, dan draft teks disimpan di renderer.
- Hasil tool dihubungkan lintas pesan ketika transcript diimpor; kegagalan tidak lagi berubah menjadi sukses. Bubble user kosong dihilangkan.
- Approval dapat diberikan dari HP atau desktop, tersedia dari dashboard/Settings, dan disinkronkan ketika diselesaikan. Always allow dibatasi pada sesi yang bersangkutan.
- Remote start/stop diserialkan, startup error selesai dengan pesan, koneksi SSE ditutup ketika Remote dimatikan atau token diganti. JSON invalid ditolak dan body dibatasi.
- UI HP menggunakan run ID untuk status pekerjaan, berlangganan sebelum mengirim prompt, tetap mendengarkan event setelah run selesai, dan memulihkan transcript setelah reconnect.
- Variabel sesi yang salah, penghapusan pesan error akibat race, field folder tersembunyi, dan composer yang tertinggal di halaman sesi baru diperbaiki.
- Nama file/folder dirender sebagai teks yang di-escape. Editor membatasi file besar/biner, memperingatkan perubahan belum disimpan, dan menolak penyimpanan versi file yang sudah berubah.
- Error pairing ditampilkan sebagai pesan di halaman; polling berhenti jika token kedaluwarsa, tanpa dialog berulang.
- Batal pada dialog commit tidak melakukan commit. Pilihan provider dan model ID manual tersedia pada HP.
- Lampiran batch bersifat atomik; path dihitung terhadap sesi penerima. Lampiran yang dihapus dapat dilepas dari main process.
- Penjagaan workspace menolak dangling symlink dan menerima nama file biasa yang diawali dua titik.

## Perbaikan UI/UX lanjutan — 0.0.3

Temuan dari inspeksi UI langsung (Electron sungguhan, profil sementara, provider stub) beserta perbaikannya.

- **Ikon dashboard tidak menyala lime saat di-hover.** Tombolnya memakai `hover:text-text`, sehingga di dalam sesi ikon berubah putih, dan saat dashboard aktif hover justru memudarkan lime-nya. Sekarang hover selalu lime, baik dari dalam sesi maupun saat dashboard terbuka.
- **Menutup Settings membuang pengguna ke view yang salah.** Tombol gigi mengembalikan view ke `session` tanpa memeriksa apakah ada sesi aktif: dari dashboard tanpa sesi, menutup Settings mendarat di halaman sesi hantu — transkrip kosong, composer tak terikat sesi, tanpa tab. Settings kini mengingat asal pembukaannya dan kembali ke sana; jika sesi asal sudah tidak ada, tujuannya dashboard.
- **Sesi yang muncul/hilang menarik pengguna keluar dari Settings.** Perubahan `activeSessionId` dari HP kini tidak mengganti view selama Settings terbuka.
- **Escape tidak menutup popover.** Popover usage serta menu model/mode di composer dan dashboard hanya bisa ditutup dengan klik di luar. Ketiganya kini menutup dengan Escape, seperti approval modal dan model picker.
- **Tombol Settings tidak punya state aktif** padahal ikon dashboard punya. Keduanya kini menyala lime saat view-nya terbuka dan membawa `aria-pressed`.
- **Judul tab terpotong tanpa tooltip.** Judul panjang kini tampil penuh lewat atribut `title`.
- **Tombol tutup tab tak terlihat oleh keyboard.** `opacity-0` hanya diangkat oleh hover, jadi pengguna keyboard men-tab ke tombol tak kasatmata. Ditambah `focus-visible:opacity-100`.
- **Focus ring bawaan Chromium** tampil sebagai halo terang yang terbaca seperti sorotan liar pada palet gelap. Diganti ring lime yang konsisten, tanpa mengubah radius sudut elemen.
- **Banner error tidak tergaya**: tombol Dismiss polos tanpa `type="button"` dan pesan panjang mendesaknya keluar layar. Kini pesan mengambil sisa ruang dan tombolnya bergaya.

Nilai `#d1fa22` yang tersebar di banyak berkas diringkas menjadi token `--color-brand` (dan `--color-brand-strong`), dinamai agar tidak bentrok dengan skala `lime-*` bawaan Tailwind.

**Bukan bug:** Settings sempat menampilkan `Version 44.3.0`. Itu artefak harness — `app.getVersion()` jatuh ke versi Electron ketika app path sementara tidak memuat `package.json`. App hasil packaging melaporkan versinya dengan benar; diperiksa langsung lewat `getAppInfo` pada `/Applications/anticode.app`.

Verifikasi: `npm run test:ui` (`scripts/verify-ui.mjs`) menegaskan tujuh perilaku di atas dengan membaca warna komputasi dan view yang aktif, bukan lewat pengamatan mata. `npm test` 122 lulus, typecheck lulus, dan `verify-desktop.mjs` tetap lulus seluruhnya.

### Temuan pengguna: sesi anticode tanpa folder tetap terkirim

Dilaporkan setelah 0.0.3 dirakit. Di dashboard, menekan kirim pada mode anticode tanpa folder membuat composer bergetar dan tombol Choose folder menyala. Di tab **New session** hal itu tidak terjadi: prompt diteruskan ke main process dan kembali sebagai error mentah `Error invoking remote method 'agent:send': Error: A code session needs a project folder` di dalam transkrip.

Penyebabnya satu cabang di `Composer`: pada tampilan hero, `blocked` dipaksa `null`. Maksudnya menyembunyikan kalimat peringatan — karena tombol Choose folder sudah ada di layar — tetapi nilai yang sama juga menjadi gerbang kirim, sehingga gerbangnya ikut terbuka. Sekarang gerbang tetap tertutup di hero; hanya kalimatnya yang disembunyikan. Tombol kirim sengaja tidak di-disable saat folder kosong, agar klik pada tombol menghasilkan getaran dan nyala yang sama seperti di dashboard, bukan diam.

Temuan turunan: sesi anticode yang sudah terlanjur berisi pesan tanpa folder tidak punya jalan keluar sama sekali — hero sudah hilang bersama tombol Choose folder, dan baris composer hanya menampilkan chip folder ketika folder sudah ada. Tombol Choose folder kini juga muncul di baris composer selama sesi code belum punya folder.

Koreksi atas perbaikan sebelumnya: focus ring lime yang dipasang global menimpa `outline-none` pada textarea composer, sehingga kotak ketik selalu berbingkai lime saat diketik. Ring kini dibatasi pada kontrol yang dapat diklik dan ditulis dengan `:where()` agar berspesifisitas nol.

Verifikasi: tiga assertion baru di `npm run test:ui` — prompt tidak sampai ke provider, Choose folder menyala setelah kirim ditolak, dan draft tidak ikut terhapus.

### 0.0.5 — lampiran tampil sebagai berkas, dan dokumen hasil bisa diunduh

Temuan pengguna: berkas yang dikirim hanya muncul sebagai teks. Composer menempelkan `\n\n[nama-berkas.png]` ke akhir prompt, jadi transkrip menyimpan nama, bukan berkasnya — gambar yang barusan dikirim tidak bisa dilihat lagi, dan berkas lain tidak bisa dibuka dari riwayat.

- **Lampiran punya rujukan sendiri.** `AttachmentRef` (nama, jenis, ukuran, path, thumbnail) ikut menempel pada blok header lampiran di riwayat model. Blok itu tidak pernah dibuang oleh pemadatan riwayat — gambar aslinya iya, untuk menghemat token — sehingga kartu tetap bisa digambar berapa giliran pun kemudian. Snapshot mengubah blok itu menjadi `{ type: 'attachment' }`, jadi desktop dan HP menggambar hal yang sama setelah app dibuka ulang.
- **Thumbnail 320 px** dibuat sekali saat melampirkan (JPEG q70, data URL) dan ikut tersimpan di `sessions.json`. Berkas aslinya tetap di tempatnya; thumbnail satu-satunya salinan.
- **Tampilan.** Gambar tampil sebagai gambar di atas bubble prompt, berkas lain sebagai kartu bernama dan berukuran; klik membuka lewat aplikasi bawaan sistem. Chip di composer juga menampilkan thumbnail, bukan hanya nama.
- **Tempel dan unggah.** Tangkapan layar dari clipboard kini bisa ditempel langsung — byte-nya distage ke folder temp karena tidak punya berkas sendiri. Jalur yang sama dipakai tombol **+** di composer HP lewat `POST /api/attachment`, yang sebelumnya tidak punya cara melampirkan apa pun.
- **Registry lampiran dipisah** ke `src/main/attachments/registry.ts` supaya IPC desktop dan server remote memakai satu daftar staging, satu aturan resolusi path terhadap folder sesi, dan satu pembebasan setelah run.

Dokumen hasil: `create_excel` dan `create_pdf` ditambahkan — sebelumnya agent hanya bisa mengubah xlsx/pdf yang sudah ada, dan hanya `write_docx` yang bisa membuat berkas baru. `create_pdf` memakai font standar PDF yang hanya mengenal WinAnsi, jadi tanda kutip tipografis dan em dash dilipat ke ASCII dan karakter di luar jangkauan diganti `?` — satu glyph asing tidak boleh menggagalkan seluruh berkas. Hasilnya muncul sebagai kartu **Open**/**Download** di bawah jawaban (dibaca ulang dari tool call yang berhasil, jadi bertahan setelah reload), dan di HP sebagai tautan unduh plus tombol `↓` pada setiap berkas di tab Files. Unduhan diresolusi di dalam folder sesi; path di luar folder ditolak dengan 400.

Verifikasi: `npm test` 129 lulus (termasuk unit baru untuk `create_excel`, `create_pdf`, pelipatan karakter, thumbnail, serta unggah dan unduh remote). `npm run test:ui` menambah tiga assertion — thumbnail terbentuk, gambar tergambar di transkrip, tidak ada sisa `[nama-berkas]` — dan satu untuk kartu unduhan dokumen. `npm run test:desktop` menambah tiga: lampiran unggahan HP sampai ke transkrip sebagai attachment yang bisa digambar, unduhan berkas hasil berjalan, dan path di luar folder ditolak. UI HP diperiksa langsung pada viewport 375 × 812.

### 0.0.5 — transkrip HP disamakan dengan desktop, dan enam temuan lain

Temuan pengguna: sesi yang sama terbaca berbeda di dua layar. Desktop merangkum satu run jadi
`ran 5 steps` dengan narasi di antaranya; HP menampilkan deretan `Explored 1 read` dan `Code …` yang
tidak habis-habis.

- **Penyebabnya dua.** Transkrip provider memecah satu run menjadi banyak pesan assistant, dipisah
  pesan tool-result di antara tiap pasangan — desktop menggambar run itu sebagai satu pesan, HP
  menggambar tiap pesan apa adanya. Di atas itu, HP mengelompokkan tool per jenis pekerjaan, jadi
  satu run pecah lagi jadi grup-grup kecil. Sekarang `foldTurns()` melipat pesan assistant berurutan
  jadi satu turn, dan tool yang berurutan masuk satu grup tanpa memandang jenisnya: `ran 5 steps`,
  `ran 2 steps · 1 failed`, persis label desktop. Langkahnya tetap ada di balik disclosure, satu
  baris per tool dengan output yang terbuka saat disentuh.
- **Grup yang sedang jalan hidup di tempat.** HP kini mendengarkan `tool_end`, bukan hanya
  `tool_start`, jadi satu elemen grup tumbuh (`working · 5 steps`) lalu mengendap jadi `ran 5 steps`.
  Titik "working" hanya muncul ketika tidak ada langkah yang menggantung — aturan yang sama dipakai
  desktop, supaya tidak ada dua penanda kerja sekaligus.
- **Sesi lama ikut dirapikan.** `importSnapshot` di desktop melipat turn dengan cara yang sama;
  sebelumnya sesi yang dibuka ulang terlihat berbeda dari sesi yang baru saja berjalan.

Lima temuan lain di rilis yang sama:

- **Menu HP.** Dropdown di kepala halaman kehilangan kartunya: teks putih polos, kolom di tengah
  layar dengan label rata kiri, dan latar halaman diredupkan supaya tetap terbaca di atas transkrip.
  `#menuDrop` sengaja tidak lagi punya properti `display` sendiri — id akan mengalahkan `.hidden`
  dan menunya tidak akan pernah bisa ditutup.
- **Kata jeda.** Menekan pause menulis "Okay, taking a break mate!" di transkrip, melanjutkan menulis
  "ah sh\*\*, here we go again" — menggantikan "▶ lanjutkan". Paragraf instruksi lanjutan yang
  sebenarnya dikirim tidak lagi muncul sebagai bubble, baik di desktop maupun di HP. Penanda jeda di
  HP dipasang ulang setiap sinkronisasi selama sesi masih berstatus paused, karena transkrip dibaca
  ulang dari server dan akan menghapusnya.
- **Setting.** Deskripsi custom provider dan tabel "Requirements and limits" di Remote dihapus.
- **Run yang berhenti sendiri di tengah jalan.** `Run paused after 100 model turns` bukan kegagalan
  model melainkan pengaman anti-loop di `AgentLoop`. Seratus giliran terlalu dekat dengan kerja
  jujur, jadi batasnya naik ke 500 (`TURN_BUDGET`) dan pesannya kini menyebut dirinya sebagai
  pengaman serta menunjuk tombol resume. Batas 2 juta token per run tetap ada; keduanya per-run,
  bukan per-sesi, jadi resume selalu melanjutkan di atas riwayat yang sama.
- **Lime yang responsif.** Ikon usage, `+` new session, ikon search dashboard, nama model, `+`
  attach, chip Auto/Default, Choose folder, label antichat/anticode, dan tombol `×` pada tab kini
  menyala lime saat didekati kursor — seperti ikon dashboard dan setting.

Verifikasi: `npm test` 129 lulus, `npm run test:ui` dan `npm run test:desktop` seluruhnya PASS
(termasuk restore sesi setelah restart, yang menyentuh pelipatan turn). Halaman HP dirender headless
pada viewport 390 × 844 untuk memeriksa pelipatan turn, label grup, grup live, dan menu — tanpa error
di konsol. Hover lime dan kedua kata jeda diperiksa lewat harness Playwright yang sama.

### 0.0.5 — lime dijadikan aturan, bukan tambalan per tombol

Temuan pengguna: panah pada tombol kirim tidak ikut berubah lime seperti tombol lain. Menambalnya
satu per satu jelas tidak cukup — yang kurang adalah aturannya, bukan satu tombol itu.

pekerjaan berikutnya tanpa perlu diingat lagi.

Sapuan menyeluruh menemukan 20 kontrol yang belum menurut: panah kirim di composer sesi dan di
dashboard, Dismiss pada banner error, `×` pada chip lampiran, baris menu approval beserta baris
penjelasnya, ketiga tombol di modal approval, Open/Download pada kartu dokumen, delapan kontrol di

Jebakan yang berulang: `hover:text-brand` di tombol tidak terlihat kalau anak elemennya menetapkan

Verifikasi: `npm run test:ui` kini menutup 20 assertion hover baru plus satu yang memastikan tombol
hapus sesi tetap merah — 34 PASS, stabil di dua kali jalan berturut-turut. Sapuan itu me-hover ulang
tiap kontrol sampai warnanya mengendap: app me-render ulang tiap lima detik karena polling status,
dan Chromium menghitung ulang `:hover` dari posisi kursor asli setiap kali itu terjadi, jadi
pembacaan sekali-jalan menghasilkan warna transisi yang menyesatkan.

### 0.0.5 — ungu dilepas dari kode sebaris

Temuan pengguna: kata di dalam kotak kode sebaris berwarna ungu. Warnanya `--color-code` (#b3b0f5),
sisa palet lama yang tidak menandakan apa pun — bukan keadaan, bukan peringatan, bukan aksi. Fontnya

Sapuan menemukan warna itu di dua tempat lain. URL pairing di Settings → Remote adalah kotak yang

Verifikasi: tiga assertion baru di `npm run test:ui` — warna font putih, latar kotak tetap
`rgb(39,39,39)`, padding tetap 6 px — sehingga sapuan warna kini 39 PASS, stabil di dua kali jalan.

### 0.0.5 — penanda jeda pindah ke kiri, dengan suara yang sama seperti grup tool

Temuan pengguna: "Okay, taking a break mate!" dan "ah sh\*\*, here we go again" muncul sebagai bubble
di kanan, seolah pengguna yang mengetiknya. Padahal itu app yang bicara tentang dirinya sendiri —
bukan pengguna, bukan model.

Keduanya dulu ditulis sebagai pesan ber-role `user`, dan role itulah yang menentukan perataan. Kini
ada jenis bagian pesan baru, `{ kind: 'notice' }`, yang menempel pada pesan assistant: rata kiri,
abu-abu 14 px, tanpa bubble — gaya yang sama persis dengan baris `ran 7 steps` — dan menjadi lime
saat kursor melewatinya. Bagian ini juga yang dipakai desktop ketika mencerminkan resume dari HP,
menggantikan `addUserPrompt`, sehingga paragraf instruksi lanjutan tetap tidak pernah terlihat.

UI HP mengikuti dengan `.notice`: penanda jeda ditulis ke transkrip, dan pesan `user` yang isinya
persis `CONTINUE_PROMPT` digambar sebagai penanda, bukan bubble — baik saat event `prompt` datang
maupun saat transkrip dibaca ulang dari server. Helper `promptLabel` yang dulu menukar teksnya di
tempat sudah tidak punya pemanggil dan dihapus.

Verifikasi: delapan assertion baru di `npm run test:ui` — penanda ada, warnanya abu, latarnya
transparan dengan sudut 0, posisinya di kiri bubble pengguna, berubah lime saat hover, dan paragraf
lanjutan tetap tersembunyi. Sapuan kini 47 PASS. Dua pemeriksaan hover paling lama di harness ikut
memakai pengulangan yang sama; salah satunya baru saja gagal palsu dengan `rgb(110,110,108)` —
warna transisi yang terbaca sebelum sempat mengendap. UI HP dirender headless: penanda di tepi kiri
16 px sementara bubble pengguna di 90 px, warna `rgb(154,154,154)`, latar transparan.

### 0.0.5 — sesi yang diarsipkan kembali sendiri saat ada perubahan dari perangkat lain

Temuan pengguna: sesi "halo" dikerjakan dari HP, tetapi di desktop tab-nya tidak muncul kembali —
sesinya terlihat seperti sudah terhapus padahal jelas hidup di HP.

Menutup tab hanya mengarsipkan sesi (`closed: true`); transkripnya tetap utuh dan tetap menerima
event. Itulah masalahnya: desktop **memang** mencerminkan run dari HP ke sesi itu — pesan, langkah,
dan token semuanya masuk — hanya saja tabnya tidak pernah dibuka lagi, jadi semua pekerjaan itu
mendarat di tempat yang tak terlihat. `surfaceSession` kini dipanggil untuk setiap event agent yang
masuk: sesi yang hanya diarsipkan dibuka kembali di tab bar. Tab aktif sengaja tidak diubah — sesi
latar yang tiba-tiba merebut layar saat pengguna sedang mengetik di tab lain adalah bug yang lain
lagi.

Arah sebaliknya ternyata punya penyakit yang sama bentuknya, dan belum pernah ketahuan: sesi yang
dihapus dari desktop tidak pernah memberi tahu HP yang sedang membukanya. `/api/approvals` — satu-
satunya permintaan yang berjalan tiap detik selama sebuah sesi terbuka di HP — menjawab 200 tanpa
peduli sesinya masih ada atau tidak, dan `pollApprovals` menelan error apa pun sebagai gangguan
koneksi sementara. Akibatnya HP duduk selamanya di layar sesi yang sudah tidak ada, dan baru tahu
saat pengguna menekan kirim. Endpoint itu kini ikut melaporkan `exists`, dan HP kembali ke daftar
sesi dengan pesan yang jelas begitu jawabannya `false`.

Verifikasi: dua assertion baru di `npm run test:desktop`. Yang pertama menutup tab, memastikan
`closed` benar-benar `true`, mengirim prompt dari HP, lalu menunggu `closed` menjadi `false` — dan
memastikan `activeSessionId` tidak ikut berpindah. Yang kedua membuat sesi, memeriksa `exists`
bernilai true, menghapusnya dari desktop, lalu memeriksa `exists` menjadi false. Pemeriksaan pertama
sudah dibuktikan gagal ketika `surfaceSession` dimatikan sementara, jadi ia benar-benar menjaga
perilaku ini, bukan sekadar lewat.

### 0.0.5 — baris penutup run: model, salin, durasi, token — dan hidup di kedua layar

Permintaan pengguna: hilangkan titik hijau, urutkan menjadi model → tombol salin → lama pengerjaan →
token terpakai, dan berlaku di HP maupun desktop.

Bagian "berlaku di kedua layar" ternyata yang paling dalam. Ringkasan run selama ini hanya hidup di
memori renderer desktop: HP tidak pernah punya baris itu sama sekali, dan desktop sendiri
kehilangannya setiap kali transkrip dimuat ulang — `importSnapshot` tidak pernah memasang `summary`,
jadi sesi lama selalu tampil tanpa penutup. Menambal HP saja akan mengulang cacat yang sama di sisi
seberang.

Karena itu ringkasan kini dicatat di main process. `bus.ts` adalah satu-satunya corong yang dilewati
setiap event, siapa pun yang memulai run-nya, jadi di sanalah run dihitung: waktu mulai dari
`prompt`, model dan token dari setiap `usage`, lalu ditutup saat `end`/`error`. Run yang tidak pernah
mendapat jawaban tidak meninggalkan giliran assistant, jadi ia sengaja tidak meninggalkan ringkasan
juga — satu-lawan-satu itulah yang membuat kedua daftar bisa dijajarkan tanpa pembukuan tambahan di
sisi penampil. Hasilnya ikut tersimpan di `sessions.json`, disajikan lewat `/api/session/:id` untuk
HP dan lewat snapshot IPC untuk desktop.

Barisnya sendiri: titik hijau dihapus; urutannya model, tombol salin, durasi, langkah dan berkas
bila ada, lalu total token. Tombol salin menyalin **jawaban model beserta biayanya** — bukan hanya
angka-angka di baris itu, yang tidak berguna kalau ditempel. Token yang ditampilkan adalah token run
tersebut, bukan akumulasi sesi, supaya sebaris dengan durasi yang juga per-run.

Tombol **Use model ID** di HP kini sejajar dengan Start, kotaknya sama besar (keduanya `flex: 1`),
warnanya lime supaya jelas berbeda, dan hanya muncul setelah ada teks di kolom Custom model ID —
lalu kolomnya dikosongkan lagi setelah dipakai.

Verifikasi: `npm run test:ui` menambah delapan assertion (model di depan, token dilaporkan, tidak ada
titik, tombol salin ada dan letaknya di antara model dan durasi, isi clipboard benar, dan keduanya
menyala lime) — 54 PASS. `npm run test:desktop` menambah dua: satu memastikan run yang selesai
mencatat model, durasi, dan token dengan jumlah ringkasan tidak pernah melebihi jumlah giliran
assistant; satu lagi memastikan baris itu kembali setelah app benar-benar direstart. UI HP dirender
headless: barisnya berbunyi "cline-pass/glm-5.3-flash ⧉ · 4s · 12,480 tokens", dan tombol Use model
ID tersembunyi sebelum diketik lalu muncul 160 × 38 px sejajar Start dengan latar lime.

### 0.0.5 — revert, gambar di dalam app, progres HP, balas kutipan, dan batas run dicabut

Lima temuan pengguna dalam satu putaran.

**Revert saat jeda.** Prompt yang salah dulu hanya bisa dijawab dengan prompt berikutnya — riwayatnya
tetap membawa kesalahan itu selamanya. `AgentSession.revertLastTurn()` membuang pertukaran terakhir
dan mengembalikan teks promptnya untuk diketik ulang. `history` (konteks yang diputar ulang) dan
`transcript` (catatan) dipadatkan serta dipangkas berbeda, tetapi selalu dari depan, jadi ekornya
tetap sejalan dan jumlah pesan yang sama dibuang dari keduanya. Ringkasan run-nya ikut dibuang karena
giliran yang diringkasnya sudah tidak ada. Tombolnya muncul di composer hanya selama sesi berstatus
jeda, dan endpoint `/api/revert` menyediakan hal yang sama untuk HP.

**Gambar terbuka di dalam app.** `shell.openPath` melempar pengguna ke Preview hanya untuk melihat
tangkapan layar yang baru saja mereka kirim. Kini gambar dibaca sebagai data URL lewat
`attachment:readImage` dan ditampilkan di atas percakapan; Escape atau klik menutupnya. Berkas selain
gambar tetap dibuka aplikasi bawaan sistem — tidak ada penampil yang masuk akal untuk xlsx di dalam
app, dan berkas di atas 40 MB juga jatuh ke perilaku lama.

**Progres HP telat dan terpotong.** Penyebabnya satu baris: `syncSession` menyimpan
`sessionEventVersion` sebelum fetch dan **membuang seluruh hasilnya** bila ada event yang tiba selama
fetch berjalan — padahal selama run berlangsung, event tiba terus-menerus. Jadi membuka sesi di
tengah run hampir selalu berakhir dengan transkrip kosong atau basi sampai halaman dimuat ulang.
Penjaganya diganti nomor urut: hanya sync yang lebih baru boleh membatalkan sync lama. Teks yang
mengalir masuk saat snapshot sedang diambil ditampung dan dipasang kembali setelah render — main
process baru mencatat giliran assistant setelah selesai, jadi teks itu memang belum ada di snapshot.
Ditambah satu re-fetch lambat tiap 8 detik selama run masih hidup, sebagai jaring pengaman.

**Reload kembali ke sesi.** Sesi terakhir yang dibuka disimpan di `sessionStorage`, jadi memuat ulang
mendarat kembali di sesi itu, bukan di daftar. Sesi yang sudah dihapus melupakan dirinya sendiri.

**Balas kutipan.** Menyeleksi bagian dari jawaban memunculkan tombol **Balas** yang mengikuti
seleksi; menekannya membawa teks itu ke atas composer sebagai kartu, seperti lampiran. Saat dikirim,
kutipan ikut sebagai blockquote di depan prompt sehingga model menjawab bagian yang diseleksi.
Tombolnya dipasang pada `mousedown` dengan `preventDefault`, karena `click` baru tiba setelah
seleksinya runtuh. Ini fitur desktop; layar sentuh punya menu seleksi sendiri.

**Batas run dicabut.** `Run paused: this run spent its 2 million token budget` bukan kegagalan, tapi
pagar. Pagar itu dilepas seluruhnya — batas giliran maupun batas token. Pekerjaan panjang harus boleh
selesai, dan berhenti di tengah justru lebih mahal: pekerjaannya separuh jadi, dan run berikutnya
memutar ulang seluruh riwayat untuk mengejar. Tombol jeda tetap ada dan menjangkau run dari kedua
perangkat; itulah tombol berhentinya. Konsekuensinya jujur: run yang benar-benar berputar tanpa henti
kini hanya berhenti bila dihentikan.

Verifikasi: `npm run test:ui` menambah delapan assertion (Balas muncul saat seleksi, kutipan mendarat
di composer, ikut terkirim, lalu bersih; Revert muncul saat jeda, mengembalikan prompt ke kolom, dan
membuang gilirannya) — 61 PASS. `npm run test:desktop` menambah satu: revert benar-benar membuang
pertukaran itu dari riwayat asli, bukan hanya dari layar — 18 PASS. UI HP diuji headless dengan
server tiruan yang menjawab lambat sambil menembakkan event di tengah fetch: snapshot dan teks
live-nya sama-sama bertahan, dan reload mendarat kembali di sesi yang terbuka.

### 0.0.5 — kartu kutipan menutup seperti popup, dan balas-kutipan sampai ke HP

Dua temuan pengguna atas fitur balas-kutipan yang baru dipasang.

**Kartunya tidak bisa ditutup dengan klik di mana saja**, dan menelan composer karena isinya tampil
utuh. Yang kedua ternyata bug tulis: kelasnya `line-clamp-3 block` — `block` menetapkan `display`
yang sama dengan yang dibutuhkan `line-clamp` (`-webkit-box`), jadi pemotongannya tidak pernah aktif
dan paragraf enam baris tampil seluruhnya. `block` dilepas. Untuk yang pertama, kartunya kini
menutup pada klik di luar composer atau pada Escape — tetap terbuka saat diklik di dalamnya, karena
di situlah balasannya diketik.

Satu jebakan yang muncul saat memperbaikinya: tombol **Balas** melayang di luar composer, dan React
menjalankan efek untuk event diskrit secara sinkron di tengah perambatan event itu sendiri. Akibatnya
`mousedown` yang **membuat** kutipan itu juga langsung menutupnya — kartunya berkedip lalu hilang.
Tombolnya sekarang ditandai `data-reply-button` dan dikecualikan dari pemeriksaan klik-luar.

**Balas-kutipan sekarang ada di HP.** Menyeleksi teks di transkrip memunculkan tombol Balas melayang
di atas seleksi; menekannya menaruh kutipan di atas kolom ketik sebagai kartu dengan pemotongan tiga
baris yang sama, dan ketukan di luar composer menutupnya. Saat dikirim, kutipannya ikut sebagai
blockquote persis seperti di desktop — kecuali pada prompt lanjutan resume, yang tidak boleh dibonceng
kutipan.

Verifikasi: tiga assertion baru di `npm run test:ui` (kutipan terpotong tiga baris, klik di luar
menutup, Escape menutup) — 70 PASS. UI HP dirender headless: tombol Balas muncul saat seleksi,
kartunya terpotong tiga baris, ketukan di luar menutupnya, dan prompt yang terkirim berbunyi
`> Tambahkan kata sunset\n\njelaskan ini`.

### 0.0.5 — kartu kutipan yang tak bisa ditutup, checklist hijau, dan gambar di HP

**Kartu "Membalas" di HP tidak bisa dihapus, dan isinya kosong.** Bukan bug tombol: `#quoteRow`

Pelajarannya bukan soal satu kartu, melainkan bahwa UI HP sama sekali tidak punya tes. Sekarang

**Checklist bercentang memakai tanda hijau.** Butir yang diakhiri `✓`/`✔`, atau ditulis sebagai kotak
tugas `- [x]`, kini memakai ✅; butir biasa tetap bertitik polos supaya centangnya tetap berarti

Perbesar/Perkecil sendiri karena viewport HP dipatok `user-scalable=no` — tanpa itu tangkapan layar
padat tetap tak terbaca.

Verifikasi: `npm run test:desktop` menambah tiga assertion dan kini 21 PASS — setiap elemen HP
